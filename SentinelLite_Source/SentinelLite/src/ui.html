Measurement details and monitoring limitations

Measures SentinelGuard's own process during the scan (sampled every second), not total system resource use. Average and peak values remain visible when the scan completes. CPU is normalized to all logical processors; memory is the Windows working set. Windows Toolhelp32 samples direct children approximately four times per second and at scan completion. Expected UI children must have the exact WebView2 Runtime name, a path under a machine-managed WebView2 installation and a valid embedded Authenticode signature; the Microsoft signer is not independently extracted. Their appearance is still recorded, but does not alone trigger a scanner warning. Unknown paths, failed signatures and every other child remain warnings during heuristic scans. Very short-lived children can be missed; zero unexpected is NOT proof that no subprocess ran. Explicit Defender scans can create a helper, and the separate Defender service is not included.

Privacy and JSON report contents — read before sharing

Includes: product name and version; export timestamp (exportedAt); a notice; scan status (active, mode, current scan path, file/skipped/finding/omitted counts, scan start time, error text, and resources containing the CPU and memory current/average/peak values, sample count, and sample timestamp). status.childProcessesObserved, childProcessesExpected, childProcessesUnexpected, childProcessImages, childProcessEntries, childProcessSampleCount, childProcessMonitoringError, and childProcessWarning are sampled Toolhelp32 results. Entries may include process name, PID, parent PID, full executable path, creation-time ticks, identity errors, signature result and classification reasoning. Full paths and timestamps may identify your system; enable redaction before sharing. Very short-lived children may be missed. current and errors can contain full folder or drive paths.

Skipped paths: skippedPaths lists full filesystem paths and readable reasons (for example, access denied, reparse point, or an archive inspection limit). status.skipLogOmitted counts any records beyond the 100,000-entry memory safety limit. Unlike the previous version, a scan may contain more identifiable filesystem metadata even when no threats were found. Defender's separate engine does not expose per-file skip telemetry.

For each flagged item: a random per-scan finding ID, full path, filename, score, severity, detection engine, written explanations, file size, last-modified timestamp, and whether manual quarantine is available. A reason may mention filenames inside an archive or a detected threat name.

Personal information that may be revealed: your Windows account name inside C:\Users\... paths, drive letters, folder names, project/document names, and Windows account SID strings (for example in Recycle Bin paths). File names and timestamps may reveal what software or documents you use and when they were modified. The skipped-path list can additionally expose folders and private filenames unrelated to detected threats. The random finding ID is not a Windows user ID.

Optional diagnostic data — OFF by default: When you tick Include optional diagnostic data, the report adds diagnosticData for up to 64 flagged files. It gathers read-only metadata at export time: file-type signature, extension, size, whether the file changed since the scan, existing scan SHA-256 where available, and for supported Windows executables the machine type, section count, relevant memory-operation imports, sampled entropy/overlay/packer signals, and locally checked embedded signature status. No executable, script, or macro is launched; no file bodies, passwords, code snippets, full import listings or browser history are exported. Large/changed/unavailable files may have partial diagnostics. Optional hashes can uniquely identify software. Redaction masks optional hashes, executable filenames and paths, but not all software characteristics. Inspect reports before sharing.

Standard report: Contains no diagnostic collection, and no scanned file is reopened during export. The report includes aggregate findingReasonsSummary counts and reportKind=manualScanFindings. File hashes shown only in the separate detail modal are excluded unless the optional diagnostics checkbox is enabled. The app never automatically uploads report data.

Sharing: the report is downloaded to your device. SentinelGuard does not automatically upload it, send telemetry, or share it with the developers. Anyone you send the JSON to can read its paths and metadata. Inspect and redact private usernames, filenames and paths before uploading or forwarding it; redaction changes those fields for later comparisons.
