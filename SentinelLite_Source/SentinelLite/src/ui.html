Privacy and JSON report contents — read before sharing

Includes: product name and version; export timestamp (exportedAt); a notice; scan status (active, mode, current scan path, file/skipped/finding/omitted counts, scan start time, error text, and resources containing the CPU and memory current/average/peak values, sample count, and sample timestamp). current and errors can contain full folder or drive paths.

Skipped paths: skippedPaths lists full filesystem paths and readable reasons (for example, access denied, reparse point, or an archive inspection limit). status.skipLogOmitted counts any records beyond the 100,000-entry memory safety limit. Unlike the previous version, a scan may contain more identifiable filesystem metadata even when no threats were found. Defender's separate engine does not expose per-file skip telemetry.

For each flagged item: a random per-scan finding ID, full path, filename, score, severity, detection engine, written explanations, file size, last-modified timestamp, and whether manual quarantine is available. A reason may mention filenames inside an archive or a detected threat name.

Personal information that may be revealed: your Windows account name inside C:\Users\... paths, drive letters, folder names, project/document names, and Windows account SID strings (for example in Recycle Bin paths). File names and timestamps may reveal what software or documents you use and when they were modified. The skipped-path list can additionally expose folders and private filenames unrelated to detected threats. The random finding ID is not a Windows user ID.

Not included: actual file contents, passwords, browser cookies, local browser history, scan authentication token, or the quarantine vault inventory. File SHA-256 hashes viewed separately in the app are not part of this export. IP addresses and email addresses are not separately collected, but could appear if you used them in a filename or path.

Sharing: the report is downloaded to your device. SentinelGuard does not automatically upload it, send telemetry, or share it with the developers. Anyone you send the JSON to can read its paths and metadata. Inspect and redact private usernames, filenames and paths before uploading or forwarding it; redaction changes those fields for later comparisons.
